\chapter{Réseaux Sémantiques}

\section{Fondements théoriques}

\subsection{Définition}

Un \textbf{réseau sémantique} (Quillian, 1968) est un graphe orienté étiqueté
dans lequel :
\begin{itemize}
  \item les \textbf{nœuds} représentent des \emph{concepts} (rectangles) ou des
        \emph{individus} (ovales) ;
  \item les \textbf{arcs} représentent des relations entre ces entités.
\end{itemize}

\noindent Les relations les plus courantes sont :
\begin{description}
  \item[\code{is-a}] relation de spécialisation / généralisation
        (Rappeur \code{is-a} Artiste) ;
  \item[\code{instance-of}] relation d'appartenance d'un individu à une classe
        (soolking \code{instance-of} Rappeur) ;
  \item[propriétés] relations arbitraires entre nœuds
        (soolking \code{signe\_chez} universal).
\end{description}

\subsection{Styles d'arcs \texttt{is-a} (cours USTHB, chapitre 5)}

Le cours distingue quatre styles d'arcs is-a, dont la combinaison permet de
représenter des règles \emph{typiques} et leurs \emph{exceptions} :

\begin{center}
\begin{tabular}{lll}
\toprule
\textbf{Style} & \textbf{Code} & \textbf{Sémantique} \\
\midrule
sorte-de strict                   & \code{S}  & règle absolue, aucune exception possible \\
sorte-de non-strict               & \code{NS} & règle typique (« en général ») \\
exception stricte                 & \code{ES} & annule définitivement une propriété héritée \\
exception non-stricte             & \code{EN} & annule typiquement une propriété héritée \\
\bottomrule
\end{tabular}
\end{center}

\noindent Une \textbf{relation niée} (lien barré, noté $\lnot R$) annule la
relation $R$ entre deux nœuds. C'est par ce mécanisme que l'on exprime, par
exemple, qu'un \texttt{ArtisteIndep} n'est \emph{pas} sous-contrat avec un
\texttt{Label} alors qu'il hérite de la classe \texttt{Artiste}.

\subsection{Héritage et non-monotonie}

L'héritage permet à un nœud de récupérer les propriétés de ses ancêtres dans la
hiérarchie \code{is-a}. La présence d'exceptions \code{ES}/\code{EN} le rend
\textbf{non-monotone} : l'ajout d'un fait (un nouvel arc) peut invalider une
conclusion précédemment dérivée. C'est l'analogue conceptuel de la logique des
défauts, mais représenté graphiquement.

\subsection{Modalités (cours USTHB, exemples 9 et 10)}

Les modalités épistémiques (\emph{croire}, \emph{savoir}, \emph{vouloir}) ne
sont \emph{pas} représentées par un style d'arc dédié. Le cours les construit
\textbf{structurellement} via des nœuds-instances de classes modales
\code{Croyances}, \code{Negations} reliés par les rôles \code{agent},
\code{objet}, \code{argument}.

\begin{tcolorbox}[notebox, title={Construction modale partitionnée}]
« Le Procureur croit que l'accusé est coupable » se modélise par :
\begin{itemize}
  \item $C_1$ \code{is-a} Croyances
  \item $C_1 \xrightarrow{\text{agent}}$ Procureur
  \item $C_1 \xrightarrow{\text{objet}}$ Culpabilité
\end{itemize}

\noindent « L'avocat de défense \emph{ne croit pas} en la culpabilité » se modélise
en niant la \emph{modalité} :
\begin{itemize}
  \item $C_2 \xrightarrow{\text{agent}}$ AvocatDéfense, $C_2 \xrightarrow{\text{objet}}$ Culpabilité
  \item $N_1$ \code{is-a} Negations, $N_1 \xrightarrow{\text{argument}} C_2$
\end{itemize}
\end{tcolorbox}

\section{Moteur d'inférence}

\subsection{Propagation de marqueurs (Fahlman, 1979)}

L'algorithme classique de Fahlman procède en trois étapes :
\begin{enumerate}
  \item Marquer le nœud source par $M_1$ et le nœud requête par $M_2$.
  \item Propager $M_1$ et $M_2$ \emph{en sens inverse} des arcs \code{is-a}
        (par BFS) jusqu'à saturer.
  \item Les nœuds doublement marqués ($M_1 \cap M_2$) répondent à la question
        d'appartenance hiérarchique.
\end{enumerate}

\subsection{Héritage avec exceptions}

Le moteur implémenté dans le projet va plus loin que la simple propagation :
il évalue effectivement la \emph{relation cible} en respectant les exceptions
strictes ou non-strictes. Trois résultats sont possibles :

\begin{center}
\begin{tabular}{ll}
\toprule
\textbf{Constante (enum)} & \textbf{Signification} \\
\midrule
\code{INHERITED}   & la relation est dérivée (positivement) \\
\code{BLOCKED}     & un arc négatif (\code{ES}/\code{EN}) bloque l'héritage \\
\code{NOT\_FOUND}  & ni affirmation ni négation trouvées dans la hiérarchie \\
\bottomrule
\end{tabular}
\end{center}

\noindent L'algorithme \code{inherits(n, r, t)} effectue un BFS depuis le nœud
$n$ : à chaque niveau, si un arc $\xrightarrow{r} t$ est trouvé, son signe
(positif/négatif) décide immédiatement (principe de proximité — la spécialisation
la plus proche prime). À défaut, on remonte la hiérarchie \code{is-a}.

\begin{lstlisting}[caption={Moteur d'héritage avec exceptions (extrait)}]
public enum Inheritance { INHERITED, BLOCKED, NOT_FOUND }

public InheritanceTrace inherits(String nodeId, String relation, String targetId) {
    Set<String> visited = new LinkedHashSet<>();
    Queue<String> q = new LinkedList<>();
    q.add(nodeId);
    visited.add(nodeId);
    while (!q.isEmpty()) {
        String cur = q.poll();
        // 1. Decision au niveau courant : arc direct (positif ou negatif)
        for (Arc a : arcs) {
            if (a.from.equals(cur) && a.to.equals(targetId)
                    && a.relation.equals(relation)) {
                Inheritance r = a.negated ? Inheritance.BLOCKED
                                          : Inheritance.INHERITED;
                return new InheritanceTrace(r, cur, /* chemin */);
            }
        }
        // 2. Sinon, remonter is-a
        for (Arc a : arcs) {
            if (a.from.equals(cur) && a.relation.equals("is-a")
                    && !visited.contains(a.to)) {
                visited.add(a.to);
                q.add(a.to);
            }
        }
    }
    return new InheritanceTrace(Inheritance.NOT_FOUND, null, ...);
}
\end{lstlisting}

\section{Interface graphique}

L'interface graphique du module \emph{Réseaux Sémantiques} est, avec celle de
la \emph{Logique Modale}, la plus visuelle du projet. Elle se compose de deux
onglets (Industrie Musicale / Système Judiciaire) et propose les fonctionnalités
suivantes :

\begin{description}
  \item[Layout hiérarchique auto-calculé] Les positions des nœuds ne sont pas
        codées en dur. Un algorithme détermine d'abord les
        \emph{composantes connexes} sous \code{is-a}, fusionne les singletons
        avec leur voisin le plus riche par relation, puis attribue à chaque
        nœud un \emph{niveau} (BFS depuis les racines). La distribution
        horizontale est uniforme par niveau, avec un \emph{zigzag} vertical
        appliqué aux niveaux trop denses.

  \item[Arcs en courbes de Bézier] Les arcs sont tracés en
        \code{quadraticCurveTo} avec un point de contrôle perpendiculaire au
        segment milieu. Cette légère courbure élimine l'effet ``spaghetti''
        des lignes droites qui se croisent. Quand plusieurs arcs relient la
        même paire de nœuds, l'amplitude de la courbe est alternée pour éviter
        leur superposition.

  \item[Hover interactif] Le survol d'un nœud illumine ses arcs sortants
        (\code{Color.brighter()}, trait épaissi), ce qui aide à démêler
        visuellement un graphe dense.

  \item[Coloration des résultats de requête] Lorsque l'utilisateur lance une
        requête « avec relation cible », les nœuds \code{INHERITED} apparaissent
        en vert avec un badge \texttt{INH}, et les nœuds \code{BLOCKED}
        apparaissent en rouge avec un badge $\lnot$. La démonstration de
        l'exception devient ainsi immédiatement lisible.

  \item[Propagation classique \emph{M\textsubscript{1}}/\emph{M\textsubscript{2}}]
        Un second panneau reproduit l'algorithme de Fahlman et colore
        l'intersection $M_1 \cap M_2$ en jaune, à des fins pédagogiques.
\end{description}

\begin{tcolorbox}[resultbox, title={Démo de l'exception en direct}]
Dans l'onglet \emph{Système Judiciaire}, sélectionner :
\begin{itemize}
  \item Catégorie source : \texttt{Accusé}
  \item Relation cible : \texttt{presume}
  \item Catégorie cible : \texttt{Innocence}
\end{itemize}
puis cliquer sur « \textbf{Évaluer la requête} » :
\begin{itemize}
  \item \texttt{Accusé} apparaît en vert (badge \texttt{INH}) — l'arc direct
        \code{presume} s'applique ;
  \item \texttt{Récidiviste} apparaît en rouge (badge $\lnot$) — l'exception
        stricte le bloque, malgré son héritage via \code{is-a Accuse}.
\end{itemize}
\end{tcolorbox}

\section{Implémentation}

L'implémentation est en \textbf{Java pur} (sans dépendance externe), reposant
sur trois classes internes au sein de \file{SemanticNetworkExample.java} :
\code{Node}, \code{Arc} et \code{SemanticNetwork}.
Le moteur d'héritage et la GUI exploitent cette structure unique.

\begin{lstlisting}[caption={Structures de base du réseau sémantique}]

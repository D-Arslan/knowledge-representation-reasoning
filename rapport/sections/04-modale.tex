\chapter{Logique Modale}

\section{Fondements théoriques}

\subsection{Syntaxe}

La \textbf{logique modale} étend la logique propositionnelle par deux opérateurs
unaires :

\begin{itemize}
  \item $\nec\varphi$ (\emph{nécessairement} $\varphi$) : $\varphi$ est vraie
        dans \emph{tous} les mondes accessibles.
  \item $\pos\varphi$ (\emph{possiblement} $\varphi$) : $\varphi$ est vraie
        dans \emph{au moins un} monde accessible.
\end{itemize}

\noindent La grammaire des formules modales est :
\[
  \varphi \;::=\; p \;\mid\; \lnot\varphi \;\mid\; \varphi \land \varphi
           \;\mid\; \varphi \lor \varphi \;\mid\; \varphi \to \varphi
           \;\mid\; \nec\varphi \;\mid\; \pos\varphi
\]
où $p$ est un atome propositionnel.

\subsection{Sémantique — Modèles de Kripke}

Un \textbf{modèle de Kripke} est un triplet $\mathcal{M} = \langle W, R, V \rangle$ :

\begin{itemize}
  \item $W$ : ensemble non vide de \emph{mondes possibles} ;
  \item $R \subseteq W \times W$ : \emph{relation d'accessibilité} entre mondes ;
  \item $V : \mathrm{Prop} \to 2^W$ : fonction de \emph{valuation} associant à
        chaque atome l'ensemble des mondes où il est vrai.
\end{itemize}

\noindent La relation de satisfaction $\mathcal{M}, w \models \varphi$ est définie
inductivement ; les cas modaux sont :

\begin{align*}
  \mathcal{M}, w &\models \nec\varphi
    &&\iff \forall v \in W,\; (w, v) \in R \Rightarrow \mathcal{M}, v \models \varphi \\
  \mathcal{M}, w &\models \pos\varphi
    &&\iff \exists v \in W,\; (w, v) \in R \land \mathcal{M}, v \models \varphi
\end{align*}

\subsection{Propriétés de la relation d'accessibilité}

Les propriétés de $R$ définissent les systèmes modaux (Tableau~\ref{tab:modal-systems}).

\begin{table}[H]
\centering
\caption{Propriétés de $R$ et systèmes modaux correspondants}
\label{tab:modal-systems}
\begin{tabular}{llll}
\toprule
\textbf{Propriété} & \textbf{Définition} & \textbf{Axiome} & \textbf{Système} \\
\midrule
Réflexive   & $\forall w,\; (w,w) \in R$               & $\nec p \to p$        & \textbf{T}  \\
Transitive  & $(w,v),(v,u) \in R \Rightarrow (w,u) \in R$ & $\nec p \to \nec\nec p$ & \textbf{S4} \\
Symétrique  & $(w,v) \in R \Rightarrow (v,w) \in R$   & $p \to \nec\pos p$    & \textbf{B}  \\
Euclidienne & $(w,v),(w,u) \in R \Rightarrow (v,u) \in R$ & $\pos p \to \nec\pos p$ & \textbf{S5} \\
Sérielle    & $\forall w,\; \exists v,\; (w,v) \in R$  & $\nec p \to \pos p$   & \textbf{D}  \\
\bottomrule
\end{tabular}
\end{table}

\section{Implémentation avec TweetyProject}

L'évaluation modale est implémentée manuellement, TweetyProject étant utilisé
pour les structures de données (\code{FolAtom}, \code{Predicate},
\code{MlHerbrandInterpretation}).

\begin{lstlisting}[caption={Construction du modèle de Kripke en Java}]
// Atomes propositionnels
FolAtom albumPlatine = new FolAtom(new Predicate("album_est_platine"));

// Mondes (ensemble d'atomes vrais dans ce monde)
MlHerbrandInterpretation w1 = new MlHerbrandInterpretation(
    List.of(albumPlatine, contrat, chanson));
MlHerbrandInterpretation w2 = new MlHerbrandInterpretation(
    List.of(concertAnnule, chanson));

// Relation d'accessibilite
Set<Pair<Interpretation,Interpretation>> pairs = new HashSet<>();
pairs.add(new Pair<>(w1, w2));  // w1 -> w2
pairs.add(new Pair<>(w1, w3));  // w1 -> w3
pairs.add(new Pair<>(w3, w3));  // w3 boucle (reflexif local)
AccessibilityRelation R = new AccessibilityRelation(pairs);

// Evaluation de □album_platine depuis w1
boolean result = evaluate(w1, new Necessity(albumPlatine), R);
// → false : w2 est successeur de w1 et album_platine est faux en w2
\end{lstlisting}

\noindent L'évaluation récursive gère les cas :
\code{FolAtom} (consulte la valuation),
\code{Negation}, \code{Conjunction}, \code{Disjunction}, \code{Implication},
\code{Necessity} (itère sur tous les successeurs),
\code{Possibility} (cherche un successeur satisfaisant).

\section{Extension temporelle (logique modale du temps)}

\subsection{Fondements}

Le cours (chapitre~3, section temporelle) propose une spécialisation
importante : faire de la relation d'accessibilité $R$ un \emph{ordre
temporel}. Les mondes deviennent des \emph{instants} ; la relation $<$
correspond au passage du temps (passé $\to$ futur). On ajoute quatre
opérateurs :

\begin{center}
\begin{tabular}{cclc}
\toprule
\textbf{Opérateur} & \textbf{Lecture} & \textbf{Sémantique formelle} & \textbf{Modal classique} \\
\midrule
$\mathbf{G}\,\varphi$ & $\varphi$ sera toujours vraie dans le futur
   & $\forall s,\; t<s \Rightarrow \mathcal{M},s\models\varphi$
   & $\nec_{\text{futur}}$ \\
$\mathbf{F}\,\varphi$ & $\varphi$ sera vraie à un moment dans le futur
   & $\exists s,\; t<s \land \mathcal{M},s\models\varphi$
   & $\pos_{\text{futur}}$ \\
$\mathbf{H}\,\varphi$ & $\varphi$ a toujours été vraie dans le passé
   & $\forall s,\; s<t \Rightarrow \mathcal{M},s\models\varphi$
   & $\nec_{\text{passé}}$ \\
$\mathbf{P}\,\varphi$ & $\varphi$ a été vraie à un moment dans le passé
   & $\exists s,\; s<t \land \mathcal{M},s\models\varphi$
   & $\pos_{\text{passé}}$ \\
\bottomrule
\end{tabular}
\end{center}

\noindent La vérité d'une proposition \textbf{change dans le temps}, ce qui est
impossible à exprimer en logique modale classique sans cette extension.

\subsection{Application --- carrière de Soolking}

Cinq instants chronologiques représentent les années-clés du parcours d'un
rappeur algérien :

\begin{center}\small
\begin{tabular}{cl}
\toprule
\textbf{Instant} & \textbf{Évènement} \\
\midrule
$t_1$ (2017) & Artiste indépendant \\
$t_2$ (2018) & Signe chez Universal \\
$t_3$ (2019) & Sort l'album \emph{Guerilla} \\
$t_4$ (2021) & Album certifié Platine \\

\subsection{Implémentation}

L'extension temporelle est codée en \textbf{Java pur} dans le sous-package
\code{rcr.modal.temporal} (\file{TemporalLogicMusic.java},
\file{TemporalLogicJustice.java}). TweetyProject ne fournit pas d'opérateurs
temporels natifs ; la sémantique du cours étant simple (ordre linéaire fini),
nous implémentons directement l'évaluation par parcours de la liste ordonnée
des instants.

\begin{lstlisting}[caption={Opérateurs temporels G, F, H, P (extrait)}]
// Instants ordonnes chronologiquement : t1 < t2 < ... < t5
static final List<String> INSTANTS = Arrays.asList("t1","t2","t3","t4","t5");

// Valuation : atome -> instants ou il est vrai
static final Map<String, Set<String>> V = new LinkedHashMap<>();

private static List<String> futurs(String t) {
    int i = INSTANTS.indexOf(t);
    return INSTANTS.subList(i + 1, INSTANTS.size());
}
private static List<String> passes(String t) {
    int i = INSTANTS.indexOf(t);
    return INSTANTS.subList(0, i);
}
private static boolean vrai(String atom, String t) {
    return V.getOrDefault(atom, Collections.emptySet()).contains(t);
}

/** G p en t : p sera TOUJOURS vrai dans le futur strict de t. */
static boolean G(String atom, String t) {
    for (String s : futurs(t)) if (!vrai(atom, s)) return false;
    return true;
}

/** F p en t : p sera vrai A UN MOMENT dans le futur strict de t. */
static boolean F(String atom, String t) {
    for (String s : futurs(t)) if (vrai(atom, s)) return true;
    return false;
}

// H et P : symetriques avec passes(t) au lieu de futurs(t).
\end{lstlisting}

\noindent L'orchestrateur \code{ModalLogicExample} appelle automatiquement la
section temporelle après la modale classique, ce qui produit une exécution
console unifiée pour le chapitre~3 du cours.
